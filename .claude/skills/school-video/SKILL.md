# 초등 활동 영상 만들기

교사는 **사진 폴더와 한 문장의 목적**만 준다. 폼을 채우게 하지 말고, 1차 완성본을 먼저 만들어 보여 준 뒤 말로 고친다.
디자인(화면 구성·글꼴·색·움직임)은 코드가 보장한다. 너의 일은 **사진을 보고 판단하는 것**(무엇을 쓰고 뺄지, 활동 이름, 자막)과 **교사의 말을 구성으로 옮기는 것**이다.

도구는 이 저장소 루트에서 실행한다(아래 `CLI`로 줄여 쓴다).

```bash
node --experimental-strip-types --no-warnings tools/school-video/cli.ts <명령> …
```

처음이면 `npm install`이 되어 있는지 확인한다(`node_modules`가 없으면 실행). Chrome 경로가 따로 있으면 `CHROME_BIN`으로 준다.

## 0. 시작 전에 확인할 것 (한 번만, 짧게)

- **사진 폴더 경로**와 **목적**(무슨 행사, 누구에게 보여 줄지). 빠진 것만 묻는다. 길이·가로세로·분위기는 말이 없으면 60초·가로·밝고 따뜻하게로 정하고 묻지 않는다.
- **개인정보 안내**: 사진을 고르려면 네가 사진을 봐야 하고, 그 과정에서 사진이 Anthropic으로 전송된다. 학생 사진이면 "학교 지침과 보호자 동의 범위 안인지"를 한 문장으로 확인받고 시작한다. 교사가 원치 않으면 사진을 보지 않고 6단계의 "사진을 보지 않는 방식"으로 만든다.
- 작업 폴더는 사진 폴더 옆에 `<사진폴더>-video` 로 만든다(원본 사진은 건드리지 않는다).

## 1. 사진 읽기

```bash
CLI ingest <사진 폴더> --out <작업 폴더> --goal "<교사가 말한 목적 문장 그대로>"
```

출력에서 촬영 날짜, 활동 초안(촬영 시각이 20분 이상 비는 곳에서 나눈 묶음), 모아보기 이미지 위치를 확인한다. 목적 문장에 있는 길이("50초")·세로 여부·학교·학년반은 초안에 자동으로 들어간다.
만들어지는 것: `photos.json`(사진 번호·시각·품질 점수), `sheets/sheet-NN.jpg`(12장씩 모아보기), `media/NNN.jpg`(줄인 사본), `spec.json`(자동 초안).

## 2. 사진 보기 — 이 스킬의 핵심

`sheets/` 의 모아보기 이미지를 **모두** Read로 본다. 각 칸의 라벨은 `#번호 · 시각 · ≈#N(N번과 비슷함) · 흐림 · 세로`다. 판단이 어려운 사진만 `media/NNN.jpg`로 크게 본다.

고르는 기준:
- **쓴다**: 아이들 표정과 활동이 잘 보이는 사진, 단체 사진(활동마다 한 장쯤), 무엇을 했는지 알 수 있는 사진(작품, 장소, 도구). 가까운 컷과 넓은 컷을 섞는다.
- **뺀다**: 눈 감음·찡그림·뒷모습만 있는 사진, 흔들림, 너무 어두움, 같은 장면의 반복(가장 좋은 한 장만), 행사와 무관한 사진(바닥, 실수로 찍힌 것), 아이가 난처해 보일 수 있는 사진(우는 모습, 옷이 흐트러진 모습 등).
- **고르게**: 특정 아이만 반복해서 나오지 않게, 가능한 한 여러 아이가 보이게 고른다. 단, 누가 누구인지 이름으로 추측하거나 적지 않는다.
- 라벨의 `≈`, `흐림`은 숫자 계산일 뿐이다. 네 눈으로 본 판단이 우선이다.
- 각 활동의 **첫 사진**은 그 활동의 대표(제목 화면의 원 안에 크게 나옴)다. 가로 사진이면서 내용이 잘 보이는 것을 맨 앞에 둔다.
- 사진 수 어림: 60초 영상이면 활동 3–4개에 **총 14–20장**(50초 16장, 40초 12장쯤).
  사진은 **한 화면에 1–3장씩 묶여** 나온다(순서대로 1장·2장·1장·3장이 반복되고, 세로 사진 둘이 이어지면 2장으로 묶인다). 한 화면은 2.6–3.4초라서 사진 한 장당 평균 약 1.9초다.
  고정 시간: 인트로 4.5초, 활동 제목 2.2초씩, 한마디 3.2초, 기록 숫자 3.6초, 마무리 4.7초. 정확한 길이와 묶음은 `build`가 알려 준다.

## 3. 구성 쓰기 (`spec.json` 고치기)

자동 초안 `spec.json`을 Read로 읽고 Edit/Write로 고친다. 형식:

```jsonc
{
  "school": "한빛초등학교", "klass": "3학년 2반",        // 모르면 school은 "우리 학교", klass는 ""
  "kicker": "2026 봄",                                  // 제목 위 짧은 문구, 14자 이내
  "title": "박물관 나들이\n현장체험학습",                 // 최대 2줄, 줄당 14자 이내
  "day": "2026.05.14 (목)", "place": "국립중앙박물관",   // day는 사진에서 읽은 값. place는 교사가 말했을 때만
  "theme": "mint",                                      // sunny(노랑·코랄) mint(초록·봄) sky(파랑·여름·차분) berry(분홍·보라) autumn(주황·가을)
  "aspect": "16:9", "targetSec": 60,                    // 세로는 "9:16"
  "pace": "auto",                                       // "auto": 길이에 맞게 속도 자동(권장). 숫자(0.7–1.5)를 쓰면 그 속도로 고정
  "intro": [4, 11, 23],                                 // 인트로 사진 최대 3장. 첫 번호가 가장 크게 나온다(가로 사진 권장). 본문에 쓴 사진을 다시 써도 된다
  "chapters": [
    { "title": "박물관 관람", "sub": "10:02 – 11:10",   // title 14자, sub 24자 이내
      "photos": [4, 2, 5, 6, 8],                         // 사진 번호. 첫 번호가 대표, 나머지는 보통 시간순
      "captions": { "4": "모두 모였어요" },              // 일부 사진에만(3장에 1장쯤), 16자 이내
      "quote": null }                                    // 교사가 직접 말해 준 한마디가 있을 때만 {"text": "…", "name": "…"}
  ],
  "focus": { "4": [0.3, 0.4] },                          // 대표·인트로 사진에서 중심이 한쪽에 치우쳤을 때 [가로 0–1, 세로 0–1]
  "stats": true,                                         // "오늘의 기록" 장면. true면 "남긴 사진 N장 · 함께한 활동 N가지"가 자동으로 들어간다.
                                                         // 교사가 인원 등을 알려 주면 [{"label":"함께한 친구들","n":28,"unit":"명"}, …](최대 4개), 빼려면 false
  "outro": { "title": "오늘도\n수고했어요!",             // 최대 2줄, 줄당 10자
             "message": "함께해 주신 선생님과 부모님께 감사드립니다.",   // 최대 3줄, 줄당 36자
             "photos": [4, 16, 24] },                    // 마무리에 놓을 사진 최대 3장(생략하면 처음·가운데·마지막 사진)
  "parentNote": "…",                                     // 학부모 안내 글(영상에는 안 들어감, 길이 제한 없음, 마지막에 교사에게 준다)
  "goal": "…"                                            // ingest가 적어 둔 목적 문장(메모용, 영상에 영향 없음)
}
```

글 쓰는 규칙:
- **보이는 것과 들은 것만 쓴다.** 사진에서 확인되지 않고 교사가 말하지도 않은 사실(장소 이름, 인원, 음식, 날씨, 일화)을 지어내지 않는다.
- **학생·교사의 이름을 쓰지 않는다.** 이름표나 옷의 글자가 보여도 옮기지 않는다. 누군가의 말(한마디)을 만들어 내지 않는다.
- 활동 이름은 사진에서 본 활동으로 붙인다("박물관 관람", "도시락 점심", "토기 만들기"). 확신이 없으면 "오전 활동"처럼 시각으로 둔다.
- 자막은 초등학생이 읽을 수 있는 쉬운 말로 짧게("두근두근 입장", "손으로 조물조물"). 유행어·이모지·과장 금지.
- 말투는 목적에 맞춘다(학부모 공유 = 따뜻하게, 아이들 상영 = 발랄하게).
- 색은 계절·행사에 맞춘다(봄 mint, 여름 sky, 가을 autumn, 운동회 sunny, 학예회 berry). "밝게"는 말투에 반영하고 색은 계절을 따른다. 교사가 색을 말하면("노란색으로") 그 색을 쓴다.
- `place`는 고유한 이름을 들었을 때만 채운다("국립중앙박물관"). "박물관"처럼 일반적인 말만 들었으면 비워 두고 제목에 그 말을 쓴다.
- 자막은 한 장짜리 화면에서 가장 크게 보인다(사진 옆 큰 글씨). 2–3장 화면에서는 사진 아래 작은 글씨로 나온다. 중요한 자막은 `build` 출력의 화면 묶음을 보고 한 장짜리 자리에 오게 순서를 잡는다.

## 4. 구성 확인

```bash
CLI build <작업 폴더>
```

- 출력의 `화면 묶음: [#4] [#1 #5] [#6] …` 에서 대괄호 하나가 한 화면이다.
- 길이는 `pace: "auto"`일 때 고른 사진은 그대로 두고 장면 속도만 조정해 목표에 맞춘다. "사진을 약 N장 줄이세요/늘리세요" 또는 "속도가 빠릅니다/느립니다" 주의가 나오면 **사진 수를 고쳐서** 다시 build 한다.
- "…자를 넘어 잘립니다" 주의가 나오면 문구를 줄여 다시 build 한다. 잘린 채로 넘어가지 않는다.
- 오류(없는 사진 번호, 빈 활동)는 고칠 때까지 진행하지 않는다.
- build는 `spec.json`을 읽기만 하고 고치지 않는다. `stills`와 `render`는 매번 `spec.json`에서 다시 구성하므로, 고친 뒤 build를 따로 돌리지 않아도 반영된다(주의 문구를 보려면 build를 돌린다).

## 5. 미리보기 → 렌더

```bash
CLI stills <작업 폴더>              # 모든 장면을 한 장에(약 30초). 가로는 preview.jpg, 세로는 preview-vertical.jpg
CLI stills <작업 폴더> --scene 5    # 5번 장면만 크게(scene-5.jpg) — 작은 글씨나 얼굴 잘림을 확인할 때
```

미리보기를 Read로 보고 직접 점검한다(각 칸은 그 장면의 중간 시점, 라벨은 장면 번호와 시작–끝 초):
- 글자가 넘치거나 다른 요소와 겹친 곳. 인트로 제목은 칸 너비에 맞춰 글자 크기가 자동으로 정해지므로, 글자 수를 줄여도 크기만 커진다 — 겹침이 없으면 고칠 필요 없다.
- 활동 제목 화면의 원 안, 인트로·마무리 사진에서 얼굴이 잘린 곳 → `focus` 조정 또는 사진 교체(`intro`, `outro.photos`).
- **넣은 자막이 모두 보이는지**(spec의 captions 개수와 화면의 자막을 대조).
- 같은 사진이 붙어 나온 곳, 내용과 안 맞는 자막.
문제가 있으면 `spec.json`을 고치고 다시 stills.

```bash
CLI render <작업 폴더>     # 가로는 video.mp4, 세로는 video-vertical.mp4 (720p, 60초 영상에 약 1–2분)
                          # 큰 화면 상영용은 --quality 1080, 파일 이름을 정하려면 --output <파일.mp4>
```

1차본은 교사에게 되묻지 않고 여기까지 한 번에 만든다. 끝나면 교사에게:
1. 영상 파일 경로(파일 전송 도구가 있으면 파일로 보낸다)와 미리보기 이미지
2. 한 문단 요약: 사진 몇 장 중 몇 장을 썼는지, 활동 구성, 길이, 뺀 사진의 이유(예: 비슷한 사진 6장, 흔들린 사진 2장)
3. 네가 **확신하지 못한 것**(추측한 활동 이름, 못 읽은 파일 등)
4. 학부모 안내 글(`parentNote`): 무슨 행사인지, 날짜, "학생 사진이 포함되어 있으니 학교 밖으로 공유하지 말아 달라"는 문장 포함
5. "고칠 점을 말로 알려 달라"는 한 줄(예: 더 짧게, 이 활동 빼기, 제목 바꾸기, 세로로, 색 바꾸기)

## 6. 말로 고치기

교사의 말을 `spec.json` 수정으로 옮기고 build → (큰 변경이면 stills로 확인) → render 한다. 고치기 전에 `spec.json`을 다시 Read 한다. 무엇을 바꿨는지 한 줄씩 알려 준다.

| 교사의 말 | 고칠 곳 |
|---|---|
| 더 짧게 / 40초로 | `targetSec`을 바꾸고 build → 주의가 나오면 그만큼 사진을 줄인다(40초 ≈ 12장, 30초 ≈ 8장) |
| 점심 부분 빼줘 | 해당 `chapters` 항목 삭제. `intro`·`outro.photos`에 그 활동 사진이 남아 있으면 함께 바꾼다(build가 알려 준다) |
| 이 사진 빼줘 / 바꿔줘 | `photos`에서 번호 삭제·교체(`CLI status`의 `unused`에 안 쓴 사진 번호가 있다) |
| 제목·문구 바꿔줘 | `title`, `kicker`, `chapters[].title`, `captions`, `outro` |
| 세로로 / 쇼츠용 | `aspect: "9:16"` (stills로 다시 확인). 가로본 `video.mp4`는 지워지지 않고 `video-vertical.mp4`가 따로 생긴다 |
| 색 바꿔줘 / 차분하게 | `theme` |
| 천천히 / 빠르게 | `pace`를 숫자로(천천히 1.2, 빠르게 0.85). 이때는 길이가 목표와 달라지는 것이 정상이다. 되돌리려면 `"auto"` |
| 우리 반 친구가 한 말 넣어줘: "…" | 해당 활동의 `quote` (교사가 말해 준 문장 그대로) |
| 숫자 장면 빼줘 | `stats: false` |

할 수 없는 것은 할 수 없다고 말한다: 음악 넣기(사용 권한이 확인된 음원 파일을 교사가 주면 스튜디오에서 넣을 수 있음), 사진 보정·얼굴 가리기, 글꼴·장면 디자인 변경, 동영상 클립 넣기.

### 사진을 보지 않는 방식 (교사가 사진 전송을 원치 않을 때)
모아보기 이미지를 읽지 않는다. `ingest`가 만든 자동 초안(시각으로 나눈 활동, 비슷한·흐린 사진 제외)을 그대로 쓰고, 활동 이름은 교사에게 순서대로 물어 채운다. 자막은 넣지 않는다. 이 방식에서는 표정·눈 감음을 걸러 내지 못한다는 점을 알린다.

## 지켜야 할 것

- 원본 사진 폴더의 파일을 지우거나 고치지 않는다. 작업 폴더 밖에 쓰지 않는다.
- 사진·영상을 저장소에 커밋하거나 외부 서비스에 올리지 않는다.
