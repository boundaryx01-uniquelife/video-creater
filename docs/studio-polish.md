# 스튜디오 완성도 개선 (studio-polish)

스튜디오(`src/studio/`, `studio/plugin.mjs`)의 알려진 한계를 해결한 작업의 설명서. 사용법은 README의 "스튜디오" 절을 먼저 볼 것.

## 1. 실행 취소 / 다시 실행

| 항목 | 내용 |
|---|---|
| 조작 | `Ctrl/Cmd+Z` 실행 취소, `Ctrl/Cmd+Shift+Z` 또는 `Ctrl+Y` 다시 실행, 왼쪽 위 "↶ 취소 / ↷ 다시" 버튼 |
| 병합 | 같은 항목의 글자·숫자를 연달아(900ms 이내) 고치면 한 단계로 합친다. 다른 항목을 고치거나 잠시 멈추면 새 단계 |
| 모드별 이력 | 모드마다 따로 보관한다. 모드를 바꿨다 돌아와도 이력이 남는다(새로고침하면 사라짐) |
| 메모리 상한 | 모드당 100단계, 이력 전체 JSON 약 24M자 중 먼저 닿는 쪽. 넘으면 오래된 단계부터 버린다 |
| 대상 | 폼 편집, 사진 추가·삭제·순서, 장면·챕터 추가·삭제, 일괄 넣기, 설정 불러오기, 초기화 모두 |

구현: `history.ts`(순수 함수 `commit/undoStack/redoStack` + `useHistory`, `useUndoKeys`). 브라우저 기본 되돌리기는 React 제어 입력과 섞여 엉키므로 입력창 안에서도 앱 이력을 쓴다.

## 2. HEIC / HEIF 사진

iPhone 기본 형식(HEIC)을 올리면 브라우저에서 JPEG로 바꿔 서버에 저장한다. 촬영 시각은 원본 HEIC의 EXIF에서 읽는다(`exifr`).

- 판별: 확장자·MIME이 아니라 파일 앞부분(매직 바이트)으로 한다. `.jpg`로 이름이 바뀐 HEIC도 변환된다.
- 변환: 브라우저가 직접 읽을 수 있으면(Safari 등) 그대로 쓰고, 못 읽으면 `libheif-js`(WebAssembly)로 디코드한다. `libheif`가 회전(`irot`)·반전을 적용하므로 세로 사진도 올바르게 선다.
- 로드: HEIC를 처음 만났을 때만 동적 `import()`로 별도 청크(약 2MB, wasm 내장)를 내려받는다. 평소 화면 로딩에는 영향이 없다.
- 실패 시 안내: 손상된 HEIC, 일부 특수 파일(깊이·Live 등), 변환 모듈 로드 실패를 구분해 한국어로 알리고 JPEG로 내보내 올리라고 안내한다. 한 번에 여러 장을 올릴 때 일부만 실패하면 정상 파일은 들어가고 실패 파일은 이름과 사유를 요약해 보여 준다.

### 라이선스 (중요)

- 선택: `libheif-js` 1.23.5 — **LGPL-3.0**. 코덱(libheif/libde265)이 LGPL이라 HEVC를 디코드하는 브라우저용 npm 패키지는 모두 LGPL이다(`heic2any`도 내부에 libheif를 담고 있고, `heic-to`는 LGPL-3.0). 허용적(MIT 등) 라이선스로 HEIC를 디코드하는 JS 구현은 사실상 없다.
- 영향: 이 도구는 로컬에서 쓰는 비공개 도구이므로 LGPL 의무가 문제 되는 경우는 드물다. 다만 **앱을 외부에 배포**하면 LGPL 조건(라이브러리 라이선스 고지, 사용자가 라이브러리를 교체할 수 있을 것, 해당 라이브러리 소스 제공 방법 안내)을 지켜야 한다. 라이브러리는 동적 `import()`로 분리된 청크라 교체가 쉽다.
- 대안:
  1. 의존성을 빼고 Safari/macOS 네이티브 디코드에만 의존(`image.ts`의 `heicToBitmap` 호출만 제거). 그러면 Chrome 계열에서는 HEIC가 실패하고 안내문이 나온다.
  2. iPhone에서 "설정 > 카메라 > 포맷 > 높은 호환성"으로 JPEG 촬영, 또는 사진 앱에서 JPEG로 내보내기.
  3. 서버에서 시스템 `libheif`/ImageMagick으로 변환(해당 도구와 HEVC 디코더가 설치된 환경에서만 가능; `sharp` 기본 바이너리는 특허 문제로 HEVC를 뺀다).
- Vite 설정: `vite.config.ts`의 `optimizeDeps.include`에 `libheif-js/wasm-bundle`을 넣어 사전 번들 대상으로 명시했다(동적 import만 있어서 발견이 늦어지는 것을 막음). 같은 파일의 `cacheDir: '.cache/vite'`는 여러 작업 폴더가 `node_modules/.vite`를 공유할 때 서로 캐시를 덮어쓰는 문제를 피하기 위한 것이다.

### 합성 HEIC 만들기(테스트)

`node scripts/gen-test-heic.mjs out.heic [--rotate] [--when "2026:11:03 14:32:10"]`  
`ffmpeg`(libx265)로 HEVC 한 프레임을 만들고 HEIF 컨테이너(ftyp/meta/iloc/iinf/iprp/iref/mdat)를 직접 조립한다. EXIF `DateTimeOriginal` 항목이 들어가며 `--rotate`는 `irot` 90° 속성을 붙인다. 사진 내용은 합성 테스트 패턴이다. ImageMagick(`identify`)로 컨테이너를 읽을 수 있고, 디코드는 `libheif-js`로 확인했다.

## 3. 장면 추가·교체, 챕터 편집

ModeVideo 모드(현장·매장·상품·학교·동아리·졸업)의 "챕터" 섹션과 "오프닝/마무리 장면" 섹션에서 한다. 행사·여행은 구조가 달라 해당 없음(행사의 "하이라이트 세션"은 기존 목록 편집을 그대로 쓴다).

- **데이터 장면**: 챕터마다 선택 상자로 종류를 고르면 기본값과 사진(방향에 맞게 챕터 사진에서 자동 선택)이 채워진다. 이미 있는 장면은 종류를 바꿀 수 있고, 같은 이름·같은 모양의 값(제목 등)은 이어받는다. "장면 삭제"로 지운다.
- **모드별 허용 종류**(`beats.ts`): 공통 = 자막 컷, 스펙 표, 숫자 요약, 인용문, 일정표, 설명+요점. 현장·매장 + Before/After, 상품·매장 + 사진 설명선, **졸업 전용** 명단 롤링·월별 타임라인. `route`(이동 경로)는 여행 영상 전용이라 노출하지 않는다.
- **오프닝/마무리 장면**: 인트로 바로 뒤 / 아웃트로 바로 앞에 같은 종류를 여러 개 넣을 수 있고, 순서 변경·복제·삭제·길이(프레임) 지정이 된다. 명단·타임라인은 기본 길이를 길게(178/128프레임) 넣는다.
- **챕터**: 추가(마지막 챕터를 바탕으로 문구 비움), 복제, 삭제(마지막 1개는 불가), 위/아래 이동. `카드 번호("공정 02 / 03")`는 순서와 개수에 맞게 다시 쓴다. 막대형 레일(졸업의 학년 막대 등)은 라벨 수가 챕터 수와 같을 때만 라벨과 현재 위치를 함께 맞춘다.
- 한계: 레일 라벨 자체와 진행형 레일의 눈금은 폼에 노출하지 않는다(기존과 동일). 새 챕터의 막대 라벨은 새 챕터의 "큰 글자"로 한 번 정해지며 이후 큰 글자를 바꿔도 라벨은 따라가지 않는다.

## 4. 렌더 대기열

`studio/plugin.mjs`가 작업을 순차 실행한다(동시 1개, 대기 최대 20개).

| API | 설명 |
|---|---|
| `POST /api/render` | `{comp, props, scale, seconds, name}` → `{id}`. 대기열에 넣는다 |
| `GET /api/renders` | 작업 목록(메모리 + 디스크에 남은 완료 영상) + 저장 공간 |
| `GET /api/render/:id` | 한 작업 상태 |
| `POST /api/render/:id/cancel` | 대기 중이면 즉시, 진행 중이면 `cancelSignal`로 중단하고 불완전한 mp4 삭제 |
| `DELETE /api/render/:id` | 완료·실패·취소 작업 삭제(mp4 + 메타) |
| `GET /api/storage` | 업로드·렌더 용량, 디스크 여유, 정리 설정 |
| `POST /api/settings` | `{rendersDays, uploadsDays, autoClean}` 저장(`.studio/settings.json`) |
| `POST /api/cleanup` | `{keep, dryRun?, rendersDays?, uploadsDays?}` 오래된 파일 삭제 |

- 남은 시간: 렌더 시작 후 진행률 2% 이상부터 `경과 × (1 − p) / p`로 추정.
- 실패: 한 줄 요약(`error`) + 원인별 안내(`hint`: 디스크 부족, Chrome 없음, 사진 주소 오류, 시간 초과, 메모리 부족) + "자세히 보기"(단계 로그, 브라우저 콘솔 오류 최근 줄, 오류 본문 앞부분).
- 완료 영상은 `.studio/renders/<id>.mp4` + `<id>.json`(이름·길이·화질)이라 서버를 다시 켜도 목록에 남는다.
- 범위 선택의 "전체 길이"로 영상 전체를 UI에서 렌더·내려받는다.

### 정리 정책

기본값: 완성 영상 14일, 업로드 사진 60일, "열 때 자동 정리" 켜짐(0일 = 삭제 안 함). 화면 아래 "저장 공간"에서 바꾼다.

- 기준은 파일의 마지막 사용 시각이다. 편집 화면이 `/uploads/…`를 불러올 때마다 시각이 갱신되므로 쓰는 중인 사진은 오래된 파일이 되지 않는다.
- 안전장치: 브라우저에 저장된 **모든 모드**의 입력에서 참조 중인 업로드, 대기·진행 중 작업이 쓰는 업로드, 진행 중 렌더 파일은 지우지 않는다. 서버 시작 시 자동 정리는 렌더만 대상(업로드는 화면을 열 때 보호 목록과 함께 정리).
- 다른 브라우저/프로필에서 편집 중인 입력은 이 보호 목록에 없다. 보관 일수를 넉넉히 두거나 0으로 꺼 둘 것.

## 5. 견고성

- **localStorage 용량 초과**: 저장이 실패하면 `data:`/`blob:` 사진 주소를 샘플 사진으로 바꿔 다시 저장하고 경고(`stripped`)를 띄운다. 그래도 실패하면 "설정 내보내기로 백업" 경고(`failed`). 사용량이 약 3.5M자를 넘으면 미리 알린다(`near`). 경고는 저장이 회복되면 사라진다.
- **죽은 blob 주소**: 이전 방문에서 서버에 저장되지 않은 사진(`blob:`)은 새로고침하면 못 쓰므로 불러올 때 샘플 사진으로 바꾸고 개수를 알린다.
- **큰 사진**: 40MB 초과는 처리하되 "대용량" 안내를 붙인다. 200MB 초과는 브라우저 메모리 보호를 위해 거절한다. 어떤 경우든 서버로는 긴 변 2560px로 줄인 JPEG만 올라간다.
- **손상·비이미지**: 빈 파일, GIF, 텍스트 등 비이미지, 끝이 잘린 JPEG, 손상 HEIC를 구분해 파일 이름과 사유를 보여 준다. 사진 1장 교체 화면에서는 기존 사진을 유지한다.
- **업로드 재시도**: 네트워크 오류·5xx는 0.5초, 1.5초 간격으로 최대 3회. 끝내 실패하면 미리보기 전용(`blob:`) 주소로 대체하고 "서버에 저장되지 않은 사진 N장" 경고와 **"서버에 다시 올리기"** 버튼을 보여 준다.
- **끌어다 놓기**: 사진 줄의 썸네일을 끌어 순서 변경, 파일을 사진 줄에 놓으면 그 챕터에 추가, 창 아무 곳에 놓으면 "사진 일괄 넣기"와 같은 배정(브라우저가 파일을 열지 않게 막음).
- **키보드·접근성**: 썸네일 ←/→ 선택, Alt+←/→ 순서 변경, 모든 입력·버튼에 이름(`aria-label`), 현재 모드 `aria-current`, 상태·경고 `role=status/alert`, `:focus-visible` 표시, 항목 ↑↓⧉✕ 버튼에 이름.

## 6. 검증

`scripts/verify-studio-polish.mjs`(Playwright)가 위 기능을 시나리오별로 실행한다.

```bash
export CHROME_BIN=<chrome 경로> NODE_PATH=<playwright가 있는 node_modules>
npx vite --port 5177 &
OUT=/tmp/studio-verify node scripts/verify-studio-polish.mjs                 # 전체
OUT=/tmp/studio-verify node scripts/verify-studio-polish.mjs --only undo,heic,scenes,robust
FULL_MODE=현장 node scripts/verify-studio-polish.mjs --only queue,full        # 렌더 포함(몇 분)
```

합성 사진(그라디언트·도형)과 합성 HEIC만 쓰며, 결과 스크린샷과 mp4는 `OUT`에 저장된다.

## 알려진 한계

- HEIC: 합성 HEIC(단일 이미지, 8비트 4:2:0, `irot`)로 검증했다. 실제 iPhone 파일의 그리드 타일 구성(여러 타일), 10비트·HDR(Display P3, 게인 맵) 파일은 합성으로 만들지 못해 검증하지 못했다. libheif는 타일을 합쳐 주지만 색 공간은 sRGB로 취급한다. Live Photo의 동영상 부분은 무시한다.
- 실행 취소 이력은 새로고침하면 사라진다(브라우저에 저장하지 않음).
- 렌더 대기열은 한 번에 1개만 실행한다(Chrome 렌더가 CPU를 모두 쓰기 때문). 서버를 껐다 켜면 대기·진행 중 작업은 사라지고 완료된 영상만 남는다.
- 행사·여행 모드에는 데이터 장면·챕터 편집이 없다(구조가 다름).
