# 스튜디오에서 사진으로 여행 영상 만들기

스튜디오(`npm run dev`)의 **여행 · 출장** 모드에서 사진 여러 장을 고르면, 사진에 들어 있는 위치(GPS)와 촬영 시각으로 머문 곳(정차지), 이동수단, 도로·철도 경로, 지형 지도를 자동으로 만든다. 만들어진 결과는 같은 화면에서 고쳐 MP4로 내보낸다. 모든 처리는 이 컴퓨터의 스튜디오 서버에서 이뤄진다.

## 처음 한 번: 지도 데이터

이동 경로·도시 이름·지도 레이어에 Natural Earth(공공 도메인) 벡터 데이터 약 150MB가 필요하다(`data/ne/`, git 제외).

```bash
npm run fetch:data          # raw.githubusercontent.com 에서 6개 파일을 받는다 (이미 있으면 건너뜀)
node scripts/fetch-data.mjs --check   # 있는지만 확인
```

데이터가 없으면 패널에 "지도 데이터가 없습니다"가 뜨고 **지도 데이터 내려받기** 버튼이 나온다(같은 스크립트를 서버가 실행). `NE_DIR` 환경 변수로 위치를 바꿀 수 있다.

## 사용 순서

1. 여행 모드 → **사진으로 여행 만들기** → 사진 선택(JPG·PNG·WebP, 카메라 원본). 선택 직후 위치 있는 사진·없는 사진·촬영 시각 없는 사진 수가 표시된다.
2. **여행 영상 만들기** → 업로드 → 사진 분석 → 정차지 → 경로 → 지도 레이어 → 지형 순으로 진행률이 표시된다. 사진 40~50장 기준 약 20~40초.
3. 결과가 오른쪽 미리보기에 나오고, 왼쪽 **만들어진 여행 편집**에서 고친다.
4. 아래 **MP4 만들기**(처음 8초 또는 전체).

> 메신저·SNS를 거친 사진은 위치와 촬영 시각이 지워져 있는 경우가 많다. 카메라 앱의 위치 태그를 켜고 찍은 원본을 올려야 한다. 서버에는 EXIF를 제거한 사본(긴 변 2000px)만 영상용으로 저장된다.

## 편집

| 항목 | 동작 |
| --- | --- |
| 제목·부제·기간 | 직접 입력 |
| 정차지 이름·부제 | 직접 입력. **이름은 가까운 도시를 자동으로 고른 추정값**이라 작은 마을·명소는 틀릴 수 있다 |
| 정차지 삭제 / 다음과 합치기 | 앞뒤 구간이 하나로 합쳐져 그 구간만 다시 계산된다(최소 2곳 유지) |
| 구간 이동수단 | 자동 추정값(거리·평균 속도·바다 비율, 이동 중 찍은 사진의 순항 속도)을 보여 주고, 6종 중 직접 지정하거나 "자동 추정"으로 되돌린다. 바꾸면 **그 구간만** 경로가 재계산된다 |
| 영상에 쓸 사진 | 정차지별 후보(위치 없는 사진 포함)를 눌러 넣고 빼기, 대표 지정, 시각 칩·자막 제목·설명 수정. 한 정차지에 최소 1장 |

경로가 바뀌면 `POST /api/travel/reroute`가 호출된다. 양 끝 좌표와 이동수단이 그대로인 구간은 이전 경로를 재사용하고, 바뀐 구간만 도로·철도·보행 경로를 찾고 지형 텍스처를 다시 만든다(같은 영역의 텍스처는 재사용). 재계산 중에도 미리보기는 곡선 경로로 즉시 갱신된다.

## 안내 메시지(예외 처리)

| 상황 | 동작 |
| --- | --- |
| GPS 사진 2곳 미만 | 오류 `few-gps` / `one-place`: 몇 장이 어디에 몰렸는지(반경)와 필요한 조건을 안내 |
| 한 곳에 몰림(시내 산책·당일치기) | 반경 3km 단위로 한 곳뿐이면 반경 350m 세부 장소로 다시 나눠 2곳 이상이면 진행(경고 `one-area`), 그래도 한 곳이면 오류 |
| 하루 안의 여행 | 참고 `same-day`: 구간 시간이 짧아 이동수단이 부정확할 수 있음 |
| 촬영 시각 없음 | 전부 없으면 오류 `no-time`, 일부면 제외하고 경고 `no-time`(개수 표시) |
| 위치 없음 | 전부 없으면 오류 `no-gps`, 일부면 지도에는 표시하지 않고 시각이 정차지 머문 시간과 맞으면 그 정차지의 사진 후보로만 사용 |
| 이동 중 찍힌 사진 | 머문 곳이 아니므로 제외하고 개수를 알림 |
| 지도 데이터 없음 | 작업 시작 전에 409 + 안내와 내려받기 버튼 |
| 지형 타일 다운로드 실패 | 경고 `terrain-fail`: 지형 음영 없이 진행. 일부만 실패하면 `terrain-partial` |
| 경로 탐색 실패 | 경고 `route-fallback`(도로·철도), `osm-fail`/`osm-noroute`(걷는 길): 해당 구간을 곡선으로 표시하고 어느 구간인지 알림 |
| 읽을 수 없는 파일(HEIC 등) | 경고 `unreadable`: 파일 이름을 알림 |

외부 접속: 지형 타일은 `s3.amazonaws.com`(AWS Terrain Tiles), 도보·자전거 경로는 `overpass-api.de`(OpenStreetMap)를 쓴다. 막혀 있어도 위 규칙대로 곡선·무지형으로 대체된다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `scripts/travel/pipeline.ts` | 핵심 파이프라인 `buildTravel`(사진 분석 결과 또는 정차지 JSON → props + 에셋), `rerouteTravel`(편집 후 바뀐 구간만 재계산). CLI와 서버가 공유 |
| `scripts/travel/analyze-photos.ts` | sharp·exifr로 사진 분석(크기·선명도·밝기·채도·dhash·팔레트·GPS·시각·카메라 → `RawPhoto`)과 영상용 JPEG 생성 |
| `scripts/travel/worker.ts` | 서버가 자식 프로세스로 띄우는 작업자(큰 지도 데이터·CPU 작업을 서버 밖에서 처리) |
| `scripts/build-travel.ts` | CLI(`npm run build:travel`). 결과는 이전과 동일 |
| `scripts/fetch-data.mjs` | 지도 데이터 내려받기(`npm run fetch:data`) |
| `studio/travel-api.mjs` | `/api/travel/*`, `/studio-assets/*` (plugin.mjs에서 마운트) |
| `src/studio/TravelPanel.tsx` | 스튜디오 패널 UI |
| `src/travel/edit.ts` | 편집 순수 함수(이름 수정·삭제·병합·이동수단·사진 선택) |

API: `GET /api/travel/status`, `POST /api/travel/fetch-data`, `POST /api/travel/upload`, `POST /api/travel/build`, `POST /api/travel/reroute`, `GET /api/travel/job/:id`, `GET /api/travel/session/:tid`. 결과는 `.studio/travel/<id>/`(props, meta, `media/`)에 저장되고 `/studio-assets/<id>/…`로 제공된다. 지도 에셋 로더(`TravelMap`)는 `/`로 시작하는 주소를 그대로 쓰고, MP4 렌더 때는 서버가 `"/studio-assets/` 주소를 `http://127.0.0.1:<포트>/studio-assets/`로 바꿔 렌더러가 받게 한다.

## 한계

- 이름은 Natural Earth 도시 목록(오프라인)에서 가까운 도시를 고르므로 작은 마을·명소는 부정확하다.
- 이동수단은 규칙 기반 추정이다. 평균 속도는 머문 시간이 섞이므로 이동 중 사진이 없으면 실제보다 느리게 나올 수 있다.
- 도로·철도 경로는 Natural Earth 간선 수준이라 골목 단위가 아니다. 도보·자전거(25km 이하)만 OpenStreetMap으로 실제 길을 따라간다.
- 정차지는 최대 7곳(가까운 곳끼리 합침). 사진 업로드는 한 장 80MB까지, 업로드 원본은 `.studio/travel-uploads/`에 남는다(필요 없으면 폴더를 지운다).
- 서버는 로컬 전용이며 인증이 없다.
